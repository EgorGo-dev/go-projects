Правила
Одновременно выполняется не более maxWorkers вызовов fn.
Results заполняется строго в порядке входного среза, а не в порядке завершения. Длина Results всегда равна длине items.
Для элемента, на котором fn вернула ошибку, в Results остаётся нулевое значение, а Failed увеличивается на единицу. Processed считает только те элементы, для которых fn действительно отработала успешно: если элемент не запускался из-за отмены контекста, он не попадает ни в Processed, ни в Failed.
Возвращается ошибка того элемента, у которого наименьший индекс — а не та, что произошла раньше по времени.
Stats возвращается вместе с ошибкой. Возвращать nil вместо *Stats при ошибке нельзя.
Если контекст уже отменён, новые вызовы fn не начинаются. Если при этом ни один элемент не вернул ошибку — возвращается ctx.Err().
При maxWorkers <= 0 возвращается ErrInvalidWorkers.
Для пустого items возвращается Stats с пустым (не nil) Results и nil в качестве ошибки.
Пояснение к правилу 4
Пусть элемент с индексом 7 упал сразу, а элемент с индексом 2 упал через секунду. Вернуть нужно ошибку элемента 2, потому что его индекс меньше. Реализация «кто первый упал, того ошибку и вернём» здесь неверна.

Требования к решению
Пишите package main и все нужные импорты.
Функцию main писать не нужно.
Стандартной библиотеки достаточно; сторонние зависимости недоступны.
Функция не должна зависать ни при каком входе.
